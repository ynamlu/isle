# 心屿（Isle）· 演示视频脚本

> 全国高校 Vibe Coding 开发挑战赛 · 参赛演示视频（时长目标 **6 分 30 秒**）
> 要求：5–8 分钟 MP4 1080p，**其中至少 2 分钟为 AI 协同过程复现**

---

## 一、录制准备

### 1.1 录制工具

| 用途 | 工具 | 说明 |
| --- | --- | --- |
| 电脑屏幕 | QuickTime Player（自带）或 OBS Studio | 录制终端 + AI 对话窗口 |
| 手机画面 | `scrcpy`（推荐）或手机自带录屏 | 需同时展示 App 与操作 |
| 剪辑 | iMovie / 剪映专业版 | 拼接、加字幕、压到 1080p |

### 1.2 录制前必做的脱敏（重要）

**必须先处理，避免泄露**：

```
□ local.properties  —— 里面的 DEEPSEEK_API_KEY 不能出现在画面里
□ 终端历史          —— 清屏，不要让 token / git 凭据出现在滚动历史
□ 桌面              —— 关掉无关窗口（聊天软件、邮箱等）
□ 手机              —— 关掉通知（免打扰模式），退出无关 App
□ 浏览器            —— 若有 GitHub 页面，确保不露出 Token 页面
```

### 1.3 画面设置建议

- 分辨率：1920×1080（1080p）
- 终端字号调大（`Cmd +` 两档），保证手机屏幕上也看得清
- 深色主题更清晰（本项目终端图也是深色）
- 录制帧率 30fps 足够

### 1.4 预演一次

正式录制前**完整走一遍**，特别是 AI 复现段的命令，确保能复现出预期结果。

### 镜头 ③　技术亮点：端侧记忆（2:25 – 3:00）

**画面**：技术文档中的「端侧记忆链路图」（fig6_pipeline.png）

**旁白**：
> 心屿最核心的差异化在这里——**长期记忆的检索完全在设备本地完成**。
> 我们把一个中文语义向量模型（bge-small-zh，量化后 24MB）打包进应用，
> 在手机上做分词、推理、向量存储和余弦召回，**全程不联网**。
> 我们在真机上跑过测试：语义相近的句子相似度 0.85，无关句子 0.39，区分度非常清晰。
> 这意味着两件事：一是**隐私安全**，二是**没有云端向量库的按量计费**。

### 镜头 ④　AI 协同复现（3:00 – 5:30）　【重点 · 2 分 30 秒】

> 这是赛事明确要求的环节。**推荐做法：以「真实会话回放 + 现场复现关键 Bug」双线进行。**
>
> 单纯回放对话会显得像"念稿"；纯现场复现又容易翻车。
> 最佳组合是：**用 1 分钟回放讲清协作方法，再用 1.5 分钟现场复现一个真实的顽固 Bug。**

#### 画面布局

左右分栏（或画中画）：
- **左/主画面**：终端（执行命令、看报错）
- **右/副画面**：AI 编程工具的对话窗口（贴 Prompt、看 AI 回复）

#### 4.1　协作方法展示（3:00 – 3:40）

**操作**：
1. 打开 AI 对话窗口，**滚动到工程骨架那一段**（真实历史记录）
2. 画面停在「我的 Prompt」与「AI 首轮方案」上

**旁白**：
> 整个项目全程使用 Vibe Coding 范式开发。但我想说明一点：
> **我不是让 AI 写代码然后复制粘贴**，而是用一套方法约束它。
> 这是最初搭骨架时的对话。我的 Prompt 里不只是"帮我写个安卓工程"，
> 而是同时给出四样东西：**分层边界、数据流、命名规范、验收标准**——
> 比如这个聊天页的 ViewModel，我明确说了"从 AppContainer 取哪三个仓储、发送流程分几步、对外暴露 StateFlow、验收标准是编译通过"。
> 这样 AI 的输出会直接落在既有架构里，几乎不需要返工。

**操作**：滚动展示一条真实的报错与修复记录（如 AGP 插件冲突）

**旁白**：
> 遇到报错时，我不描述现象，而是把**完整证据链**回灌给 AI：报错原文、依赖树、环境版本、
> 以及我已经试过的方案。这样 AI 才能精准定位，而不是让我挨个试。

#### 4.2　现场复现顽固 Bug（3:40 – 5:10）　【核心亮点】

> **选择这个 Bug 的理由**：它有清晰的「失败 → 定位 → 修复 → 通过」闭环，
> 且涉及真实的工程难点（Kotlin 编译器版本与依赖元数据的兼容性），**复现 100% 可控**。

**复现步骤（照做即可）**：

**Step 1 — 制造失败（3:40 – 4:00）**

在终端执行（先展示当前是正常状态）：
```bash
cd ~/Desktop/Isle
./gradlew :app:compileDebugKotlin --rerun-tasks
# → BUILD SUCCESSFUL（先证明现在是好的）
```

然后**打开 `gradle.properties`，把 Kotlin 版本改回旧版**（或在 `libs.versions.toml` 里把 `kotlin = "2.3.21"` 改成 `"2.2.10"`），重新编译：

```bash
./gradlew :app:compileDebugKotlin
```

终端打印出：
```
e: Module was compiled with an incompatible version of Kotlin.
   The binary version of its metadata is 2.4.0, expected version is 2.2.0.
```

**旁白**：
> 现在我把 Kotlin 版本回退一格，模拟当时遇到的真实问题——
> 引入视觉库 Haze 之后，编译直接失败。报错说：这个库的元数据版本是 2.4.0，
> 但编译器只能读到 2.3.0。

**Step 2 — 引导 AI 定位（4:00 – 4:35）**

在 AI 对话框中输入（**这是真实的引导 Prompt**）：

```
编译报错：
e: Module was compiled with an incompatible version of Kotlin.
   The binary version of its metadata is 2.4.0, expected version is 2.2.0.

环境：Gradle 9.6.0 / AGP 9.4.1 / Kotlin 2.2.10 / KSP 2.2.10-2.0.2
请先不要猜。我想知道升级 Kotlin 到能读 2.4.0 元数据的版本是否可行，
但前提是 KSP 生态必须仍然可用（Room 依赖 KSP）。请先查证 KSP 的版本情况，再给结论。
```

**画面**：AI 开始分析（可加速播放），给出结论：KSP 最新为 2.3.12，**没有 2.4 系列**；
但编译器版本 N 可读 metadata 至 N+1 → **Kotlin 2.3.x 恰好能读 2.4.0**，且 KSP 可用。

**旁白**：
> 注意我这个 Prompt 的关键点：**先不给方案，而是先给约束和验证要求**。
> 我明确告诉 AI "KSP 必须仍然可用"，让它去查证而不是随便给一个版本号。
> AI 的结论是：KSP 没有 2.4 系列，但 Kotlin 2.3.x 刚好能读 2.4.0 的元数据——这是最优解。

**Step 3 — 应用修复（4:35 – 5:00）**

修改 `gradle.properties`：
```properties
android.builtInKotlin=false
android.newDsl=false
```
修改版本目录：
```toml
kotlin = "2.3.21"
ksp = "2.3.12"
```

重新编译 —— 此时可能又遇到第二个报错（AGP 新 DSL 不兼容），正好展示**第二轮引导**：

```
⛔ The 'org.jetbrains.kotlin.android' plugin is not compatible with AGP's 9.0 new DSL
   (`android.newDsl=true` is enabled by default).
```

**旁白**：
> 果然又撞上第二个问题——AGP 9 的新 DSL 与独立 Kotlin 插件不兼容。
> 这里有个经验：**官方报错往往自带解法**，仔细读完报错信息，它直接告诉我要加 `android.newDsl=false`。

**Step 4 — 验证通过（5:00 – 5:10）**

```bash
./gradlew :app:compileDebugKotlin --rerun-tasks
# → BUILD SUCCESSFUL，0 警告
./gradlew connectedDebugAndroidTest
# → 2 tests, 0 failures
```

**旁白**：
> 编译通过，而且仪器化测试也全绿。整个过程我没有凭经验瞎试——
> 每一步都由报错、依赖树和测试结果驱动。这就是我理解的 Vibe Coding：
> **AI 负责产出，我负责定义约束和验收**。

#### 4.3　本段的拍摄提示

- **提前排练 3 次以上**，确保命令不出错
- 修改文件时**放慢动作**，让观众看清改了哪一行
- AI 回复可**加速播放**（4x–8x），只保留关键结论
- 若现场 AI 响应慢，可**预先打开已生成好的对话页面**作为替代（如实说明"这是当时的真实记录"）
