# 第一部分 · 立项与原型

## 1. 立项

### 1.1 起点

项目最初是一个 Web 原型。用户提出：

> “这个项目可以重构为原生安卓 App 吗？并且 AI 只接入 DeepSeek。”

进一步明确：

> “AI 闺蜜、女友、男友、朋友等等，可以自定义角色性格简介，并且有记忆保留。”

随后收敛为：

> “心屿，仅安卓；文档聚焦当前产品。”

### 1.2 100 分钟 MVP

2026-10-15 15:51 开始，约 100 分钟跑通核心闭环：

```text
原生 Android 工程
  → Room 三表
  → DeepSeek SSE 流式
  → 角色 CRUD
  → 端侧 ONNX 记忆
  → Compose 界面
```

### 1.3 当时的四个硬约束

1. 代码必须落在 UI / Domain / Data / 基础设施四层；
2. 使用手写 `AppContainer`，不引入 DI 框架；
3. 状态一律 `StateFlow` 单向输出；
4. 高风险能力先定义接口与失败降级路径。

这四条后来一直保留到当前版本。

---

## 2. 技术选型与关键决策

| 决策 | 原因 |
| --- | --- |
| Kotlin + Compose 原生 | 只做 Android；端侧 ONNX 集成更直接 |
| Room 三表 | 角色 / 消息 / 记忆职责清晰 |
| OpenAI 兼容协议 | 不绑定单一厂商，地址/模型/Key 可切换 |
| 手写 AppContainer | 结构透明，降低 AI 生成隐式依赖 |
| 端侧 bge-small-zh-v1.5 | 隐私、离线、无额外向量服务费用 |
| ABI 拆分 | ONNX 四套原生库会让 APK 膨胀到 185MB |
| 单 Activity + Compose | 页面状态集中，导航简单 |

### 2.1 端侧记忆

- 模型：`bge-small-zh-v1.5` int8，23.9MB；
- 维度：512；
- 池化：CLS + L2 归一化；
- 召回：语义 0.8 + 关键词 0.2 + 重要度 0.1；
- 失败降级：关键词匹配。

### 2.2 为什么保留“记忆”

普通聊天机器人每次从零开始；心屿希望做到：

> “它不是每次重新认识你，而是带着对你的了解出现。”

这是心屿的核心差异化，也是后续迭代一直保留的能力。

## 3. 早期开发期问题

| # | 问题 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | `Cannot add extension with name 'kotlin'` | AGP 9 内置 Kotlin 与独立插件冲突 | 移除独立 Kotlin 插件 |
| 2 | Kotlin 元数据 2.4 与编译器 2.2 不兼容 | Coil 3.6.3 强制拉高 stdlib | 降级 Coil 到 3.4.0 |
| 3 | Haze 2.0.1 元数据过高 | 编译器版本不足 | 升级 Kotlin 2.3.21 + KSP 2.3.12 |
| 4 | `new DSL` 与 Kotlin 插件冲突 | AGP 9 新 DSL | `android.newDsl=false` |
| 5 | 输入法拉不起来 | 第三方输入法懒加载 / 插件服务未及时初始化 | `adjustResize` + `imePadding` + 焦点后自动重试拉起 |
| 6 | 聊天图片模糊 | 复用了头像 512px 压缩 | 聊天图独立 1600px |
| 7 | 消息同毫秒排序错位 | 只按 timestamp 排序 | `ORDER BY timestamp DESC, id DESC` |
| 8 | 流式 `[DONE]` 与 `onClosed` 双回调 | 结算逻辑重复 | `AtomicBoolean` 单次结算 |
| 9 | ONNX 张量泄漏 | 未关闭 `OnnxTensor` | 三层 `use {}` |
| 10 | 编辑角色跳到列表末尾 | 更新时丢了 `createdAt` | 保留原 `createdAt` |
| 11 | 备份与“仅存本机”矛盾 | `allowBackup=true` | `allowBackup=false` |
| 12 | 图片选择弹窗文案错误 | 聊天页复用了头像选择器 | 支持标题参数 |
| 13 | PDF 页数与 Markdown 不一致 | 未重导 / 阅读器缓存 | 重导并核对页数 |

# 第二部分 · 情绪支持重构

## 5. 评分复盘

校赛评分：

| 维度 | 得分 |
| --- | --- |
| 解题有效性与实用价值 | 28 / 35 |
| 方法创新性与意图控制 | 21 / 25 |
| 工程质量与架构设计 | 15 / 20 |
| 用户体验与产品精细度 | 15 / 20 |

复盘结论：

- 技术创新被认可，但“情感陪伴”被看成弱需求；
- 工程质量与 UX 是短板；
- 需要从“角色聊天”转向“有边界的情绪支持”。

## 6. 方向调整

用户提出：

> “可以是有针对性的情绪疗愈或心理支持，比如针对大学生心理减压的痛点。角色可以是闺蜜、老师或家人，舍弃恋人。”

并进一步设计：

> “情感分析 Agent → 安全策略路由 Agent → 人设生成 Agent；高危情绪立刻强制拦截角色扮演。”

产品收敛为：

- 三种固定角色：闺蜜 / 老师 / 家人；
- 八个场景；
- 五种对话模式；
- 多智能体安全路由；
- 本地匿名账户；
- 记忆折叠与管理。

## 7. 关键实现

### 7.1 安全路由

```text
SafetyEngine
  → ConversationOrchestrator
      ├─ CRISIS：固定危机话术，退出角色，不调用模型
      ├─ HIGH：安全确认 + 真人资源，不调用模型
      └─ NORMAL：角色/场景/倾听/分析/呼吸
```

设计原则：

- 危机判断不能完全交给 LLM；
- 固定话术包含 12356、120/110、学校心理中心/辅导员；
- 危机内容不写入长期记忆；
- 输出侧再用 `ResponseValidator` 拦截 AI 身份暴露、危险方法、倾听模式给建议。

### 7.2 本地匿名账户

用户要求：

> “登录核验采取本地。”

实现：

- 昵称 + 密码；
- PBKDF2WithHmacSHA256，随机盐，210,000 次迭代；
- 恢复码只显示一次；
- 5 次失败锁定；
- 后台 60 秒应用锁；
- 删除账户清空本地数据；
- 明确不做学籍/实名核验。

### 7.3 记忆管理

- 记忆 Tab 按角色折叠；
- 默认收起；
- 展开只读查看；
- 点「管理」进入单角色记忆管理；
- 支持搜索、编辑、删除、清空；
- 返回/切换 Tab 保持展开状态。

### 7.4 角色与场景

- 去掉恋人；
- 新增老师/家人；
- 首页 8 个场景；
- 场景先选角色，AI 主动开场；
- 场景提示词每次只推进一个小步骤。

## 8. 重构期问题

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 英文危机表达带空格输入不稳定 | `adb input text` 的分词限制 | SafetyEngine 增加去空格匹配 |
| 测试时微信输入法无法输入 | 输入法服务未及时初始化 | 新增输入框焦点重试，并复测第三方输入法 |
| 记忆折叠返回后丢失 | 状态存在 `remember` | 移入 ViewModel |
| 记忆条目误触跳转 | 整行可点击 | 记忆条目只读，角色组「管理」进入管理页 |
| 聊天页记忆入口过深 | 入口在聊天右上角 | 移除，统一放到记忆 Tab |

# 第四部分 · AI 协同方法

## 14. Prompt 链示例

### 14.1 立项

用户：

> “这个项目可以重构为原生安卓 App 吗？并且 AI 只接入 DeepSeek。”

AI：

- 先确认模型 ID 与 baseURL；
- 提示 API Key 反编译风险；
- 给出原生 Android、KMP、WebView 三种路线对比；
- 在用户确认前不改文件。

### 14.2 安全架构

用户：

> “情感分析 Agent 先分析情绪，安全策略路由 Agent 检测高危，人设生成 Agent 输出。”

AI：

- 把“三个 Agent”拆成检测 / 路由 / 生成 / 校验；
- 强调危机判断不能完全交给 LLM；
- 提出本地规则 + 确定性状态机；
- 设计固定危机话术与 12356 资源。

### 14.3 本地账户

用户：

> “登录核验采取本地。”

AI：

- 明确本地无法做邮箱/学籍核验；
- 设计 PBKDF2 + 恢复码 + 应用锁；
- 把账户数据用 Keystore 加密；
- 明确“匿名本地账户”的能力边界。

## 15. 排错闭环

每次问题按四步处理：

```text
1. 保留报错原文
2. 定位根因（依赖 / 配置 / 状态 / 设备）
3. 最小修复
4. 编译 / 单测 / 真机验证
```

例子：

- 记忆折叠返回丢失 → 先复现，确认是 `remember` 状态，再移入 ViewModel；
- 英文危机输入不稳定 → 确认 adb 输入限制，再让 SafetyEngine 支持去空格匹配。

## 16. 用户偏好

- 删除/动设备前先问；
- 密钥只显示掩码；
- 不要 FAB、不要悬浮加号；
- UI 全局统一、液态玻璃、有温度；
- 开发者信息固定三行；
- 文档聚焦当前产品、不强调“比赛版”；
- 演示视频不提交 Git；
- 源码包不带 `local.properties`。

## 17. 经验总结

1. **先定边界，再堆功能**：情绪支持不是“角色越多越好”；
2. **安全不能交给模型自由发挥**：确定性路由 + 固定话术；
3. **本地优先**：账号、记忆、向量都尽量留在设备；
4. **状态要放在能活过返回的地方**：ViewModel 而不是 `remember`；
5. **文档与代码同时演进**：页数、版本号、入口、角色都要同步；
6. **真机是最终裁判**：输入法、异常数据、返回栈只有真机能暴露。
