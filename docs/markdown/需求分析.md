# 心屿（Isle）· 需求分析

## 导读

这份文档回答三个问题：

1. 心屿为什么要做，解决的是谁的什么问题；
2. 当前版本做了哪些功能，哪些不做；
3. 每个需求怎样才算“做完了”。

它写给评委、指导老师和第一次接触项目的同学。读完后，即使不做开发，也应该能判断：这个产品是否有用、边界是否清楚、功能是否完整。

---

## 一、背景与问题

### 1.1 为什么做心屿

大学生遇到情绪问题时，常见的处境是：

- 想找人说说，但不想让室友、同学或家人担心；
- 去了心理咨询，却觉得“还没严重到那个程度”；
- 半夜情绪上来，找不到可以立即回应的人；
- 试过通用 AI 聊天，但聊完就忘，下一次还要重新解释自己。

心屿想补的是这段空白：**在专业帮助之前、日常情绪之后，提供一个随时可用、又不会越界的倾听空间。**

它不替代心理咨询，也不承诺“聊完就好”。它只做三件小事：

1. 让用户先把情绪说出来；
2. 帮用户把事实、感受和需要分开；
3. 在用户愿意的时候，推进一个今天能完成的小动作。

### 1.2 现有方案为什么不够

| 现有方案 | 优点 | 不足 |
| --- | --- | --- |
| 通用 AI 聊天 | 随时可用、表达自由 | 没有情绪边界，容易变成“陪聊”；不记得用户；危机处理不可控 |
| 心理咨询 | 专业、可靠 | 需要预约，门槛高，不能随时使用 |
| 树洞/匿名社区 | 有真实回应 | 回复质量不稳定，隐私和安全感依赖平台 |
| 情绪记录 App | 结构化、可回顾 | 偏工具，缺少“被回应”的体验 |

心屿的取舍是：保留 AI 的随时可用，但用角色、场景、安全路由和本地记忆把它约束在一个更安全、更连续的范围里。

### 1.3 设计原则

- **先安全，再陪伴**：高危/危机表达不交给模型自由发挥；
- **先倾听，再建议**：默认不急着讲道理；
- **本地优先**：账户、聊天、记忆尽量留在手机；
- **有边界**：不提供恋人角色，不做诊断，不利用危机变现；
- **可解释**：用户能看到当前情绪、风险和模式，而不是只看到一句回复。

## 二、用户与场景

### 2.1 目标用户

**主要用户：在校大学生。**

他们可能面临：

- 期末、考研、求职带来的持续压力；
- 宿舍关系、家庭期待、亲密关系带来的情绪消耗；
- 夜间失眠、反刍、低动力；
- “想被听见，但不想被认识的人知道”的表达需求。

**次要用户：需要轻量情绪支持的成年人。**

他们不一定有明确心理问题，只是需要一个不评判的对话入口。心屿不收集年龄、学籍、身份证，也不做未成年人专属模式；如果用户处于危机状态，应用会优先引导真人资源。

### 2.2 典型使用场景

| 场景 | 用户状态 | 心屿提供什么 |
| --- | --- | --- |
| 期末复习焦虑 | 脑子很乱，看不进书 | 先把焦虑说出来，再拆成今天能做的一件事 |
| 面试失败 | 觉得自己很差劲 | 接住挫败感，区分“这次没成”和“我不行” |
| 宿舍关系 | 想说又怕撕破脸 | 梳理感受、需求和边界，准备沟通句式 |
| 家庭冲突 | 不想被说教 | 稳定、温和的家人角色，先听完再说 |
| 失眠 | 停不下来反刍 | 30 秒呼吸或感官落地，不追求立刻睡着 |
| 低动力 | 什么都不想做 | 不催促，先允许停一会儿，再找一个最小动作 |
| 孤独 | 想连接但开不了口 | 树洞模式，先陪一会儿 |
| 只想被听见 | 不需要建议 | 只倾听、不打断、不评价 |

### 2.3 用户真正需要的

把用户访谈和场景拆开后，核心需求可以归成四类：

1. **被听见**：不被打断、不被评价、不被急着给建议；
2. **被记住**：不用每次都重新解释自己；
3. **被接住**：情绪很强时，有一个稳定的回应，而不是角色崩坏；
4. **被交给真人**：当情况超出 AI 能力时，明确告诉用户去哪里求助。

## 三、需求范围

### 3.1 当前版本做什么

- 三种固定角色：闺蜜、家人、老师；
- 八个预设场景和五种对话模式；
- 本地匿名账户、应用锁、恢复码；
- 流式对话、图片输入、停止生成、失败重试；
- 端侧长期记忆、按角色隔离、折叠管理；
- 高危/危机安全路由、固定话术、真人资源；
- 情绪手账、保存到相册、二维码分享；
- 四栏导航、启动封面、关于页、心理援助资源；
- 模型服务代理，真实 Key 不进 APK。

### 3.2 当前版本不做什么

| 不做 | 原因 |
| --- | --- |
| 恋人角色、恋爱/暧昧扮演 | 避免情感依赖和内容风险 |
| 心理诊断、治疗、疗效承诺 | AI 不具备专业资质 |
| 收集年龄、身份证、学籍 | 降低隐私和合规风险 |
| 让模型决定危机路由 | 高危场景必须由确定性规则先拦截 |
| 云同步、跨设备找回 | 当前版本优先本地隐私 |
| 语音输入、TTS、生物识别 | 后续版本再评估 |

优先级说明：P0 是必须完成，P1 是重要，P2 是可选。

| 编号 | 需求 | 用户故事 | 验收标准 | 级别 |
| --- | --- | --- | --- | --- |
| 01 | 本地匿名账户 | 我想不填手机号就开始使用 | 昵称 + 密码可注册；不联网；可锁定、可删除 | P0 |
| 02 | 三角色 | 我想选择不同的陪伴方式 | 小屿 / 阿岚 / 林深可切换；不提供恋人关系 | P0 |

| 06 | 本地记忆 | 我不想每次重新解释自己 | 自动抽取；按角色隔离；可搜索、编辑、删除、清空 | P0 |
| 07 | 安全路由 | 我情绪很糟时不想被角色扮演敷衍 | 高危/危机不调用模型；固定话术；展示真人资源 | P0 |

| 09 | 四栏导航 | 我想快速找到场景和记忆 | 首页 / 场景 / 记忆 / 我的；二级页隐藏底栏 | P1 |
| 10 | 模型服务 | 我想换自己的模型 | 支持 OpenAI 兼容地址、模型、Key；可测试连接 | P1 |
| 11 | 心理援助资源 | 我需要知道去哪里求助 | 设置页常驻 12356、120/110、学校心理中心 | P0 |
| 12 | 关于页 | 我想知道这个项目是谁做的 | 介绍、技术亮点、开发者、指导老师、联系方式 | P2 |

## 五、非功能需求

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| N01 | 隐私 | 账户、聊天、记忆、向量默认只存本机；不收集手机号/邮箱/实名 |
| N02 | 安全 | 真实模型 Key 不进 APK；代理令牌可撤销；模型白名单限制 |
| N03 | 可靠性 | 危机路由不依赖网络；模型失败有明确提示；流式停止不丢内容 |
| N04 | 性能 | 首屏约 1.4 秒；普通回复流式输出；端侧向量不阻塞主线程 |
| N05 | 可用性 | 首次使用 3 分钟内完成第一次对话；关键按钮可点击区域足够 |
| N06 | 兼容性 | Android 8.0+；适配第三方输入法；适配 arm64/armv7 |
| N07 | 可维护性 | 单模块分层；安全规则有测试；文档与代码同步 |
| N08 | 合规边界 | 不做诊断/治疗；危机时转介真人；不利用危机场景变现 |

## 六、关键用户流程

### 6.1 第一次使用

```text
安装 → 品牌封面 → 创建本地账户 / 先体验
→ 首页选角色 → 选场景 → AI 主动开场 → 开始对话
```

目标是让用户在 3 分钟内完成第一次有效对话，而不是先读一长串说明。

### 6.2 日常对话

```text
打开应用 → 解锁 → 选角色 → 输入 / 发图片
→ 流式回复 → 记忆抽取 → 下次对话召回
```

### 6.3 情绪很强时

```text
用户输入高危/危机表达
→ 本地规则识别
→ 暂停角色扮演
→ 固定安全话术 + 真人资源
→ 用户确认安全后，才恢复自由聊
```

这条流程不依赖模型，网络不好时也能工作。

### 6.4 管理记忆

```text
记忆 Tab → 按角色折叠 → 展开查看
→ 点「管理」→ 搜索 / 编辑 / 删除 / 清空
```

### 6.5 生成手账

```text
深度对话 → 点 ✨ → 提炼金句 → 生成图片
→ 保存到相册 → 分享到朋友圈/小红书
→ 二维码回到落地页
```

## 八、验收标准

当前版本的验收以“可演示、可复现、可解释”为准：

- 新用户能完成注册 → 选角色 → 对话 → 记忆 → 手账；
- 危机词能触发固定话术，不调用模型；
- 记忆按角色隔离，删除账户能清空；
- 60 个 JVM 测试通过，2 个仪器化测试通过；
- 真机安装、启动、聊天、图片、手账可用；
- 源码包可用 `./scripts/reproduce.sh` 复现构建。

## 九、风险与约束

| 风险 | 影响 | 当前应对 |
| --- | --- | --- |
| 模型输出不稳定 | 回复质量波动 | 固定 Prompt 骨架 + 输出校验 + 安全兜底 |
| 危机识别误判 | 漏判或误判 | 本地规则 + 保守策略 + 真人资源常驻 |
| 代理被滥用 | 成本增加 | 模型白名单 + 令牌轮换 + 预算告警 |
| 本地数据丢失 | 换机/卸载后无法恢复 | 当前明确提示；后续增加加密导出 |
| 图片响应慢 | 体验下降 | 控制图片尺寸；后续优化压缩与链路 |
| 评审设备差异 | 输入法/系统行为不同 | 自动重试键盘；提供 Gboard 备选说明 |

## 十一、结论

心屿的需求并不复杂：让一个正在难受的人，能在一个安全、安静、记得他的地方，把话说完。

真正难的是边界：什么时候该接住，什么时候该停下来，什么时候该把用户交给真人。当前版本把这些问题拆成了可测试的需求和可复现的流程，后续功能也应继续围绕这条边界展开。
